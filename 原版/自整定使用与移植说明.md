## 先了解边界：候选与验收是两件事

继电法给的是模型近似下的参数起点。`PORTABLE_TUNE_CANDIDATE`只表示实验数据通过了周期、振幅与漂移门槛，不能叫实机温控验收通过。

只有使用原PID内核（包含P死区、D门槛、滤波和双向输出限速）做真实闭环试跑，再依据项目指标验收，才可决定是否保存。模块和示例均不写Flash。现在已有的定稿参数不能因为产生候选就自动覆盖。

## 工作点与实验流程

1. 上层先用旧PID或人工控制接近目标，测出大致维持功率bias。模块不包含从冷机自动找bias的功能。
2. start后模块输出固定bias，等待输入在目标±settle_band内；每拍斜率足够小，而且整个settle_ms窗口的峰峰值不超过settle_span，才开始实验。bias不准时会等待超时，需重新设定。
3. 继电实验：输入到目标+hysteresis切低功率，到目标-hysteresis切高功率，中间保持。高/低分别为bias±relay_step。配置校验拒绝越过输出范围，运行时不静默裁剪。
4. 跳过启动过渡周期，记录完整“低转高→下一次低转高”的实际时间、温度极值、周期中心和确认执行的高低输出。使用最近3~6个完整周期检查一致性；可以在max_cycles预算内等待收敛。
5. 取得候选、故障或取消时output都置0。上层必须立即实际写0。终态保持，不会自动重启；需要明确start新一轮。
6. 上层明确请求候选试跑，用当前实际输出初始化控制器状态；这能减轻跳变，不承诺任何工况无扰接管。保留旧配置；试跑失败停热并恢复旧配置，恢复加热还需上层明确操作。

## 最小调用方式

```c
/* 在且仅在一个.c定义实现宏；其他.c只include */
#define PORTABLE_TUNE_IMPLEMENTATION
#include "通用自整定.h"

static PortableTune tuner;
static PortableTuneConfig cfg;

/* 上电函数 */
portable_tune_reset(&tuner);
portable_tune_defaults(&cfg);
/* 按新项目重配目标、bias、step、温度边界和时间门槛 */
if (portable_tune_start(&tuner, &cfg, now_ms)) {
    /* 统一下发tuner.output */
}

/* 主循环定期执行，即使传感器没有新帧 */
portable_tune_tick(&tuner, now_ms, permit_heat);
/* 检查状态，统一下发tuner.output */

/* 只有确认收到一帧新的有效数据才执行 */
portable_tune_update(&tuner, measured, actually_applied_output,
                     sample_arrival_ms, permit_heat);
/* 检查状态，统一下发tuner.output */
```

上述语句放在各自函数内。所有入口都要按状态处理输出；允许升温只通过permit_heat还不够，项目保护应拥有最终停热权。`portable_tune_get_result`只在有效候选终态返回1。

## 时间、样本与执行器对账

- 用真实单调毫秒计数，不用“调用次数×0.5秒”。传入主机接收新样本的同一时钟；不能把写CSV时刻当采样时刻。每次间隔及总实验长度必须小于2^31毫秒。
- `tick`应在主循环频繁执行，例如每10~100ms；没有新样本也调用。模块无法在整个CPU/主循环停止时自己关硬件，项目必须保留通信与硬件看门狗。
- 两次相同毫秒的update不重复计入实验，但这不能识别“旧帧换了时间戳”。新帧序号、数据有效性、滤波钳位持续触发等由上层判断，旧帧禁止重复喂入。
- `applied_output`是此前真正已经写给执行器的值，不是刚生成的新命令。没有功率硬件回读时，可用确认成功的下发值，但只能证明软件发送，不能证明可控硅/加热器确实执行；需要额外电流核对。
- `actuator_grace_ms`必须覆盖正常命令延迟与采样周期。每次新命令都有独立确认期限，逾期即失败；新数据迟到不能复活过期命令。0只适用于同一时间点立即回读确认的特殊场景，普通周期采样不要设0。
- 实验输出不能经过普通PID的5%/秒限速，否则不是近似方波。如果驱动自身限制/整形导致无法按时达到命令，本模块应失败，不能继续硬套继电公式。试验仍保留项目允许功率范围、联锁、超温与断线停热。
- 实际温度输入应沿用生产滤波链，滤波延迟也包含在辨识对象中。量化误差允许用output_tolerance配置，但要求继电半幅大于其两倍。

| max_hysteresis_ratio | 0.45 | hysteresis/温度半振幅上限，不能大于0.5 |
| output_tolerance | 0.6 | 输出回读允许误差，覆盖百分比整数四舍五入 |

## 候选参数计算与单位

令h为每周期实际确认高/低输出均值之差的一半，a为温度峰峰值的一半，Pu为同方向切换间隔秒数。窗口内通过一致性检查后：

```
Ku ≈ 4*h/(π*a)
Kp = kp_factor*Ku
Ti = ti_factor*Pu
Td = td_factor*Pu
Ki = Kp/Ti
Kd = Kp*Td
```

继电存在滞回、采样延迟、非对称热过程等，Ku只是近似估计，不声称精确临界增益。限制滞回/振幅比、中心漂移和周期一致性可以剔除明显不适用数据，但不能证明任何未知对象都可稳定控制。

默认工程系数0.2/1/0选择保守PI候选，**不是某个标准Z-N表，也不保证无超调**。需要PID时自行配置td_factor（例如0.125只是候选规则示例），同样必须试跑。结果为秒制并联增益，不能再次乘/除采样周期；屏幕SetData放大编码是项目层职责。

正常PID的P死区、D每拍门槛及D滤波不属于继电实验的继电开关，但闭环验证时必须恢复原配置。自动产生Kd不代表它能穿过D门槛或改善实际温控。

## 候选验收工具

`通用自整定验收.h`不运行PID，不负责功率，也不自动接受参数。试跑开始时调用start，之后对每个真实新样本update，同时无帧时也tick。

配置warmup_ms为允许热透时间，window_ms为随后连续统计窗口；全程限制maximum_overshoot。统计窗口输出minimum/maximum/mean/count/inside，按峰峰、均值偏差和落在±tolerance内的样本占比判断。比例是样本占比，不是时间加权占比，因此采样周期需相对稳定。允许超调是相对目标，不代替绝对温度保护。

接入示例在开始整定和开始试跑时都要求permit及当前量程有效。试跑/通过后的新样本间隔一旦超过原PID的max_dt（预设1秒）就停热，避免把较长真实间隔静默截为1秒；小于min_dt的密集样本等待累计够周期后再计算。开始试跑不会写Flash。

示例使用热透25分钟+统计5分钟、±0.5℃占比100%、峰峰≤1℃、均值误差≤0.5℃、全程超调≤2℃。这些是可修改的验收条件，不代表已在真实设备上验证。PASS后仍需正常控制器持续执行联锁和失联监测。

验收失败原因：1配置非法、2联锁拒绝、3时钟倒退、4样本超时、5无效数值、6超调超限、7末段指标未达标。自整定错误原因见头文件的PORTABLE_TUNE_*宏及portable_tune_reason。

## 移植与存储

只使用标准C的float、unsigned char、unsigned long、float.h、limits.h；无数学库调用（测试仿真需要math.h）。所有实例由调用方分配，一个实例对应一条测量/输出通道，无全局共享动态状态。

8051 RAM较小，实例及配置建议置于xdata。头文件中没有写死xdata/芯片类型；示例仅在__C51__下选择xdata。C51建议采用LARGE内存模型编译集成示例，避免实现函数局部变量挤占内部DATA；最终项目自行确认链接、栈、代码空间与时序预算。相同实例不可在主循环/中断并发使用，跨线程需项目层同步。

原PID、实验器、验收器的实现宏各自在一个编译单元定义。仅编译接入示例即可包含三份实现；不要同时把编译检查入口加入实际项目。示例是接入框架，不含具体硬件驱动、参数页或Flash版本迁移。

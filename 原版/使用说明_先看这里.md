# 通用加热 PID 模块

从 2026-10-19 现场定稿版提取，保留验证过的位置式 PID 计算顺序。源目录“自整定”的内核与现场版 SHA256 一致。原PID控制模块保持不变。2026-10-20新增独立的通用自整定及候选验收模块，见`自整定使用与移植说明.md`；旧屏幕自动整定分支仍仅作原件存档，未启用。

## 文件怎么用

- `通用比例积分微分.h`：核心，复制这一个文件即可。源码 ASCII，兼容旧工具链编码。
- `调用示例/多路加热调用示例.c`：单板/多板调用示例，七路只是示例数量。
- `移植与修改说明.md`：参数、接口、调度和保护边界。
- `验证测试/数值回归验证.py`：Python 数值回归；`验证测试/编译检查.c`：C51 编译检查入口。
- `原版参考/原版算法存档.h`：原件（GBK），用于追溯，不加入新工程编译。
- `来源与校验.json`、`验证结果.md`：来源及本次验证记录。

## 最快接入

在且仅在一个 `.c`（也可以就是 `main.c`）中写：

```c
#define PORTABLE_PID_IMPLEMENTATION
#include "通用比例积分微分.h"

static PortablePid pid;
static PortablePidConfig cfg;

/* 上电初始化 */
cfg = portable_pid_heater_config();
portable_pid_reset(&pid);

/* 每次新的、有效的测量到来 */
if (portable_pid_step(&pid, &cfg, 100.0f, measured_c, elapsed_s)) {
    /* 把 pid.output 交给 PWM 或串口驱动 */
}
```

上面的初始化和计算语句放进你自己的函数中。其他 `.c` 只 include，不再 define 实现宏。状态由调用方分配，头文件中没有七路全局状态定义，因此不会各编译单元各拿一份状态。多通道用数组，每路有自己的历史和时间戳。

**10 / 0.05 / 20 只是在当前加热板上验证过的参数。**通用的是算法接口，新设备的热惯性、功率、传感器、周期或输出单位变了，都要重新验证参数。这里的通用范围是正增益、单向加热，输出从 0 起；制冷、正反转电机、双向执行器需要另行扩展。


中文命名说明：文件和子目录已改为中文；`.c` 示例采用 GBK 编码以适配 C51 中文包含路径。原版算法存档保持原始字节，编译产物中的历史源文件名仅供追溯。函数、类型和宏名称保持不变。

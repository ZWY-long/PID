# 移植与修改说明

## 本次保留的算法

`e = target - actual`；P 死区只清 P 使用的误差，I 仍使用真实误差。

`integral += e * dt`；上拍输出饱和且误差继续推向饱和方向时暂停积分。积分贡献 `Ki * integral` 限制在输出区间。

`d_raw = -(actual-last_actual)/dt`；第一拍 D=0。每拍测量变化小于 `d_step_deadband` 才清零，严格小于（等于不清零）；随后 `d_filt += d_alpha*(d_raw-d_filt)`。

`out = Kp*e_P + Ki*integral + Kd*d_filt`；先输出限幅，再双向变化率限制。`last_out` 保留未量化浮点值。`raw_out` 是限幅之后、限速之前的值。

原件有历史注释与实现不一致（例如写“下降不限速”、10%/秒、旧采样周期）。本模块以实际代码为准：上升下降都限速，定稿 5%/秒，默认 0.5 秒。

## 配置表

| 字段 | 加热板预设 | 含义 |
|---|---:|---|
| kp | 10 | 输出百分点 / ℃ |
| ki | 0.05 | 输出百分点 / (℃·秒) |
| kd | 20 | 输出百分点·秒 / ℃ |
| output_min/max | 0 / 100 | 输出范围；当前仅支持 min=0 |
| p_deadband | 0.3 | 输入单位，℃ |
| d_step_deadband | 0.1 | 每拍输入变化阈值，℃；对应原版 1.0×0.1 |
| d_alpha | 0.2 | 每拍滤波系数，不是秒；周期变化会改变滤波时间特性 |
| slew_rate | 5 | 输出百分点 / 秒；0 表示禁用 |
| default_dt | 0.5 | 秒，dt 太小时的替代值 |
| min_dt / max_dt | 0.05 / 1.0 | 秒；小于下限用 default_dt，大于上限截为上限 |

配置要求有限数；增益非负；Ki=0 或大于 0.0001（原版有此积分限幅阈值，因此本版本不接受其间的小正值）；d_alpha 在 0~1；周期满足 min≤default≤max；输出上限为正。

`portable_pid_step` 返回 0 表示参数/输入无效，不修改状态；返回 1 表示已更新。调用前必须 reset。外部要保证实际量程合理，不能只靠浮点有限值检查防范任意巨大数运算溢出。

## 新项目通常改哪里

1. 从加热预设得到配置，再按新设备设置 kp/ki/kd、输出上限、死区、微分阈值、周期和限速。
2. 在驱动层把测量换成真实物理量，输出换成设备需要的 PWM/功率。当前参数按摄氏度和 0~100% 定义；若改用 0~1 输出，kp/ki/kd、输出上下限和限速都要除 100。
3. 每路只在新样本到来时计算，传同一路两次新样本之间的秒数，不能重复消费旧帧。长时间断流先停热、reset，恢复后重新开始，不能把 max_dt 截断当作失联保护。
4. 实际写整数功率时在驱动层量化，例如非负百分比 `power=(unsigned int)(pid.output+0.5f)`；不要把这个整数写回 last_out。取整策略由项目指定，Python round 在半整数处与此规则不同。
5. 改参数、暂停或切手动时明确选择重置策略。本版 reset 是清零重新起步，**不承诺无扰切换**。在线改 Ki 会按原版方式重新解释积分；建议停热 reset 后改参数。

## 边界与项目职责

传感器 ADC 换算、7点中值、尖峰钳位、EMA、通信去重、UI、Flash 和报警不属于 PID 核心；没有复制进来。沿用旧参数时，应保留/复核原测量链及采样周期。输入测量应使用有效数值，显示取整不能反过来参与控制。

超温、断线、短路、联锁、失联等情况由上层立刻写零/断开执行器，再 reset PID；紧急停热不经过每秒5%的限速。模块不代替硬件保护，也不直接操作 IO。

## 与原内核有意不同之处

- 固定全局七路改成调用方持有的独立实例；算法常量变成配置。
- 对空指针、非法配置、NaN/Inf输入返回失败；原版缺省输出范围回退改成显式拒绝非法范围。
- Ki=0 时清积分，防止长时间纯P运行产生隐藏积分；开启/关闭I请reset。定稿 Ki=0.05 不受此项影响。
- slew_rate=0 禁用限速；输出上限运行中降低时增加末端限幅，保证输出不超过新上限。
- 原版 dt 回退和截断规则保留，但上下界可配置；自动整定没有接入。

原屏幕 `SetData` 的 100/5/200 仅是存储编码（Kp×10、Ki×100、Kd×10）；本模块直接写 10.0/0.05/20.0，无需存储放大。新项目自行实现参数持久化和版本迁移。

## C51 注意事项

采用 C89 结构，无 malloc、stdint 依赖、递归。小 RAM 的 C51 工程可将实例数组放到项目选择的 xdata 区；不要直接复制原工程的类型定义或工程绝对路径。主循环串行调用，避免同一实例在中断与主循环重入调用。单头实现宏仅出现一次。
